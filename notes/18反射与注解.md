# 反射与注解笔记

对应 `18-junit-reflect-annotation-proxy` 中的 `demo1junit`～`demo4proxy`，整理单元测试、反射、注解与 JDK 动态代理。

## 1.JUnit 单元测试：

单元测试用于单独检查一个方法的行为，不必每次都从整个项目的 `main()` 开始运行。本模块使用 **JUnit 4**，导入的是 `org.junit.Test`。

```java
@Test
public void testGetMaxIndex() {
    Assert.assertEquals(-1, StringUtil.getMaxIndex(""));
}
```

- 本例测试方法写成 `public void`，无参数，并标记 `@Test`。
- `Assert.assertEquals(期望值, 实际值)` 自动比较结果，不相等时测试失败；也可以在最前面添加失败提示。
- 仅打印结果不等于验证正确性；断言才能明确表达预期。
- 测试要考虑正常值、空字符串、`null` 等边界。

当前 `getMaxIndex("abcdefg")` 返回的是长度 7，测试也断言为 7。若按方法名理解为“最大有效下标”，应该是 6。**测试通过说明代码符合断言，不代表断言一定符合需求。**

## 2.什么是反射？

反射是在程序运行时，获取类的信息，并动态创建对象、访问字段和调用方法的机制。

```text
Class 对象
├── Constructor：构造方法 → 创建对象
├── Field：字段 → 读取、修改数据
└── Method：方法 → 调用行为
```

普通写法是事先知道类，再直接 `new Dog(...)`、调用方法；反射把“类有哪些成员、要操作哪个成员”也变成运行时可以处理的数据，适合通用工具和框架。

## 3.获取 Class 对象：

`ReflectDemo1` 演示了三种写法：

```java
Class<Student> c1 = Student.class;
Class<?> c2 = Class.forName("com.ranan.demo2reflect.Student");
Student student = new Student();
Class<?> c3 = student.getClass();
```

| 写法 | 使用场景 |
| --- | --- |
| `类名.class` | 编译时已经知道类型 |
| `Class.forName("全限定类名")` | 类名来自字符串，例如配置 |
| `对象.getClass()` | 已有对象，获取其实际运行类型 |
| `getName()` | 获取包名和类名，例如 `com.ranan.demo2reflect.Student` |
| `getSimpleName()` | 获取简单类名，例如 `Student` |

在本例相同类加载器下，三种方式取得同一个类的 `Class` 对象。它描述类本身，不是某一个学生实例。笔记使用 `Class<?>` 等泛型写法，减少源码中原始类型 `Class` 带来的不明确转换。

## 4.获取成员：普通获取与 Declared 获取

| API | 获取范围 |
| --- | --- |
| `getConstructors()` | 当前类的 public 构造方法 |
| `getDeclaredConstructors()` | 当前类声明的所有构造方法，包括 private |
| `getFields()` | public 字段，包括继承而来的 public 字段 |
| `getDeclaredFields()` | 当前类声明的字段，包括 private，不包含父类声明的字段 |
| `getMethods()` | public 方法，包括继承的方法 |
| `getDeclaredMethods()` | 当前类声明的方法，包括 private，不包含父类声明的方法 |

单数形式用于精确查找，例如 `getDeclaredField("hobby")`、`getDeclaredMethod("eat", String.class)`。**获取到 private 成员，不等于已经有权限使用它。**

构造方法不继承；反射返回的成员数组也不要依赖其排列顺序与源码一致。

## 5.Constructor：创建对象

```java
Class<Dog> c = Dog.class;
Constructor<Dog> con = c.getDeclaredConstructor(String.class, int.class);
Dog dog = con.newInstance("小狗", 2);

Constructor<Dog> empty = c.getDeclaredConstructor();
empty.setAccessible(true);
Dog another = empty.newInstance();
```

`Dog` 的无参构造方法是 private，因此调用前需放开访问检查。查找构造方法时传入的是**参数类型**，创建对象时传入的是**参数值**；`int.class` 与 `Integer.class` 不一样，查找时要匹配实际声明。

`getParameterCount()` 可以取得参数数量。

## 6.Field：读取与修改字段

```java
Dog dog = new Dog("小狗", 2);
Field field = Dog.class.getDeclaredField("hobby");
field.setAccessible(true);
field.set(dog, "play");
String hobby = (String) field.get(dog);
```

| API | 含义 |
| --- | --- |
| `getName()` | 字段名 |
| `getType()` | 字段声明的类型，返回 Class 对象 |
| `get(对象)` | 读取这个对象的字段值，返回 Object |
| `set(对象, 值)` | 修改这个对象的字段值 |

这里 `field` 描述“hobby 这个字段”，而 `dog` 指定“读取哪一只狗的数据”。静态字段属于类，反射访问时对象参数可以传 `null`。

反射写字段不会自动调用 setter，所以也不会自动执行 setter 中的校验。

## 7.Method：调用方法

```java
Dog dog = new Dog("小狗", 2);
Method eat = Dog.class.getDeclaredMethod("eat", String.class);
String answer = (String) eat.invoke(dog, "bone");

Method privateEat = Dog.class.getDeclaredMethod("eat");
privateEat.setAccessible(true);
privateEat.invoke(dog);
```

`invoke(调用对象, 实际参数...)` 执行方法并返回结果；无返回值方法返回 `null`，静态方法的调用对象可传 `null`。方法名相同但参数不同，需要分别查找对应重载。

若被调用的方法内部抛出异常，反射调用通常以 `InvocationTargetException` 包装它，可通过 `getCause()` 查看原始异常。

## 8.之前遇到的 IllegalAccessException：

`SaveObjectFrame` 已通过 `getDeclaredFields()` 找到 `Dog` 的私有字段，但直接执行 `field.get(obj)` 时仍会检查访问权限，所以此前出现了：

```text
IllegalAccessException: cannot access ... with modifiers "private"
```

当前代码已在读取前添加：

```java
field.setAccessible(true);
Object value = field.get(obj);
```

`setAccessible(true)` 表示请求关闭该反射对象的 Java 语言访问检查，并不是把字段本身改成 public。它也不是对所有类都有效：受到模块封装等限制时仍可能失败。日常业务优先使用公开方法，反射用于确有需要的通用处理。

## 9.反射与泛型擦除：

`ReflectDemo3` 对 `ArrayList<String>` 反射调用 `add(Object)`，加入了 `9.1` 和 `true`。

```java
List<String> list = new ArrayList<>();
Method add = list.getClass().getDeclaredMethod("add", Object.class);
add.invoke(list, 9.1);
```

泛型主要在编译阶段检查，擦除后 `ArrayList.add()` 接收 Object。反射绕过了这次编译期类型检查，但并没有让混入的对象变成 String；后续按 String 读取时可能出现 `ClassCastException`。

## 10.SaveObjectFrame：反射的通用处理练习

处理过程：接收 Object → `getClass()` 获取实际类 → 遍历字段 → 读取字段名、类型和值 → 追加写入文本文件。

因此同一个 `saveObject(Object obj)` 可以处理 Dog、Student、Teacher，而不用为每种类单独写一套输出代码。

当前实现的几个边界：

- 使用 `getDeclaredFields()`，只处理当前类声明的字段，没有向父类逐层查找。
- 文件路径是相对工作目录的 `18-junit-reflect-annotation-proxy/src/obj.txt`，不是固定相对 Java 文件所在位置。
- 当前 `PrintStream` 未关闭，宜使用 try-with-resources；`obj == null` 也尚未处理。
- 这是把字段转成文本的练习，不是完整的对象序列化框架，也没有实现从文件恢复对象。

## 11.什么是注解？

注解（Annotation）是附加在类、方法、字段等位置的**元数据标记**，与 `//`、`/* */` 这样的注释不同。注解本身不会自动执行业务，编译器、注解处理器或运行时程序读取它后，才会做对应处理。

例如 `@Override` 供编译器检查重写关系，JUnit 读取 `@Test` 来识别测试方法，Lombok 的 `@Data` 等由编译期处理器生成代码。不能把所有注解都理解成“运行时通过反射执行”。

## 12.自定义注解与属性：

```java
public @interface MyBook {
    String name();
    int age() default 18;
    String[] address();
}

@MyBook(name = "Anran", address = {"Beijing", "Shanghai"})
class BookDemo { }
```

声明注解使用 `@interface`。属性写成无参方法的形式；有 `default` 的属性可以省略，没有默认值的必须填写。常见属性类型包括基本类型、String、Class、枚举、注解，以及这些类型的一维数组。

当本次只需要填写名为 `value` 的属性时，可以省略 `value =`：

```java
@A("ANRAN") // 等价于 @A(value = "ANRAN")
```

其他属性只要有默认值，也不影响这个简写规则。注解类型隐式继承 `java.lang.annotation.Annotation`；反射取得注解对象后，通过 `注解对象.属性名()` 读取值，不要把源码中的标记理解为普通的手写 `new` 表达式。

## 13.元注解：规定注解怎么使用

```java
@Target({ElementType.METHOD, ElementType.TYPE})
@Retention(RetentionPolicy.RUNTIME)
public @interface MyTest2 {
    String value();
    double price() default 100;
    String[] adddress();
}
```

这里保留源码中的属性名 `adddress`，使用和解析时必须与声明一致。

| 元注解 | 作用 |
| --- | --- |
| `@Target` | 限制注解可标记的位置 |
| `@Retention` | 指定注解保留到哪个阶段 |

常用位置：`TYPE` 类/接口等类型声明、`FIELD` 字段、`METHOD` 方法、`PARAMETER` 参数、`CONSTRUCTOR` 构造方法、`LOCAL_VARIABLE` 局部变量。

| 保留策略 | 含义 |
| --- | --- |
| `SOURCE` | 只保留在源代码中 |
| `CLASS` | 保留到 class 文件，默认策略；通常不能通过运行时反射获取 |
| `RUNTIME` | 保留到运行时，可以通过反射读取 |

**运行时要解析自定义注解，就要使用 RUNTIME。** 当前 `A`、`MyBook` 没有声明 Retention，因此默认是 CLASS；`MyTest`、`MyTest1`、`MyTest2` 则设置了 RUNTIME。

## 14.解析类和方法上的注解：

`AnnotationDemo3` 分别解析 Demo 类和它的 `go()` 方法：

```java
Class<Demo> c = Demo.class;
if (c.isAnnotationPresent(MyTest2.class)) {
    MyTest2 annotation = c.getAnnotation(MyTest2.class);
    System.out.println(annotation.value());
    System.out.println(annotation.price());
    System.out.println(Arrays.toString(annotation.adddress()));
}

Method method = c.getDeclaredMethod("go");
MyTest2 annotation = method.getAnnotation(MyTest2.class);
```

| API | 作用 |
| --- | --- |
| `isAnnotationPresent(注解类型.class)` | 判断是否存在该注解 |
| `getAnnotation(注解类型.class)` | 获取指定注解，不存在时返回 null |
| `getDeclaredAnnotation(...)` | 获取直接声明在当前元素上的指定注解 |
| `注解对象.value()` 等 | 读取属性值 |

类上的注解和方法上的注解是两个独立位置，要获取对应的 Class 或 Method 再解析，不会因为类有注解就自动让每个方法都有同样的注解。

## 15.模拟 JUnit：注解和反射结合

`AnnotationDemo4` 使用自定义 `@MyTest(count = 3)`，表示标记的方法需要执行三次：

```java
for (Method method : AnnotationDemo4.class.getDeclaredMethods()) {
    if (method.isAnnotationPresent(MyTest.class)) {
        int count = method.getDeclaredAnnotation(MyTest.class).count();
        for (int i = 0; i < count; i++) {
            method.invoke(annotationDemo4);
        }
    }
}
```

最终 Test1 执行 1 次，Test3 执行 3 次；Test2、Test4 没有标记，不执行。反射枚举方法的顺序不保证固定，因此不要求 Test1 一定先执行。

当前简化版假设被标记的方法无参数且可访问，也没有为每个测试单独捕获异常；某个方法抛异常会中断后续执行。完整测试框架还需要处理方法合法性、断言、异常收集和测试报告。

## 16.JDK 动态代理：在方法调用前后加入处理

`demo4proxy` 中，`StarService` 是服务接口，`Star` 是真正唱歌、跳舞的实现类。`ProxyUtil` 为 Star 创建一个也实现 `StarService` 的代理对象；`Test` 通过这个代理调用方法。

```text
调用者 → StarService 代理 → 准备话筒或场地 → Star 真正表演 → 返回结果
```

```java
Star star = new Star("Anran");
StarService proxy = ProxyUtil.createProxy(star);
proxy.sing("Happy Birthday to You");
System.out.println(proxy.dance()); // 输出真实方法返回的“谢谢！谢谢！”
```

这里“准备话筒，20万元”“准备场地，30万元”只是打印提示，并没有实现真正的收费。

### 代理对象是怎么创建的？

```java
StarService proxy = (StarService) Proxy.newProxyInstance(
        ProxyUtil.class.getClassLoader(),
        star.getClass().getInterfaces(),
        (proxyObject, method, args) -> {
            // 在真实方法前增加处理
            return method.invoke(star, args);
        }
);
```

上面是便于理解的简化写法；当前源码使用匿名 `InvocationHandler`，并按方法名分别打印准备话筒或场地的信息。

| 参数 | 作用 |
| --- | --- |
| 类加载器 | 加载运行时生成的代理类 |
| 接口数组 | 指定代理要实现哪些接口；本例包括 `StarService` |
| `InvocationHandler` | 规定每次通过代理调用接口方法时执行什么 |

这个 JDK 代理依赖接口。生成的对象可以作为 `StarService` 使用，但它不是 `Star` 对象，不能强转成 `Star`。`s.getClass().getInterfaces()` 取得 Star 直接实现的接口。

### 一次调用经过哪里？

执行 `proxy.sing("Happy Birthday to You")` 时，Java 把这次调用交给 `InvocationHandler.invoke(proxyObject, method, args)`：

1. `proxyObject` 是代理对象本身；`method` 表示这次调用的 `sing`；`args` 包含歌曲名。
2. 代理根据 `method.getName()` 判断要准备话筒，打印提示。
3. `method.invoke(star, args)` 用反射调用真实 Star 的 `sing()`。
4. 代理把真实调用的结果交还给调用者。`sing()` 是 void，结果为 null；`dance()` 返回字符串。

委托调用时要传真实对象 `star`，不要把代理对象再传进去，否则可能反复进入同一个 `invoke()`。当前源码已经使用 `return method.invoke(s, args)`，所以 `dance()` 的返回值可以正确传回 `Test`；若写成调用后固定 `return null`，返回值就会丢失。

### 我们讨论的理解：代理究竟改了什么？

已经有接口实现类，但希望在它的方法调用前后添加日志、权限检查或耗时统计等操作时，可以让调用者通过代理使用它。**效果像是给方法加了处理步骤，实际没有修改原实现类的方法。**

```java
StarService direct = star;  // 直接调用真实方法
StarService wrapped = proxy; // 先经过代理，再调用真实方法
```

两者都符合 `StarService` 接口，这是接口多态的体现。只有经由 `wrapped` 的调用才经过附加处理；直接调用 `star.sing()` 仍执行 Star 原来的方法。因此“就地修改”可以作为直觉类比，但不能理解为原对象的方法体被改写了。

这种做法适合多个方法需要统一处理的场景，例如记录日志、检查权限、统计耗时。代理提供统一的介入位置，具体的日志或权限规则仍需自己编写。若只是一个简单方法加一行代码，直接修改实现类也可能更直观。

### 多接口实现与动态代理有什么区别？

| 做法 | 解决的问题 | 谁编写方法实现？ |
| --- | --- | --- |
| 类实现多个接口 | 让一个类具备多套接口规定的能力 | 开发者在类中实现各接口方法 |
| JDK 动态代理 | 在调用已有接口方法时，统一加入额外处理并委托真实对象 | Java 在运行时生成代理类；开发者编写 `InvocationHandler.invoke()` |

两者可以一起使用：`Star` 可以实现多个接口，代理也可以实现传给 `newProxyInstance()` 的多个接口。多接口实现回答“对象能提供哪些方法”，代理回答“通过代理调用这些方法时怎样处理”。

**代理对象确实实现了接口，但你不用手写一个代理类并逐个实现 `sing()`、`dance()`。** Java 生成这些方法，并把调用转给同一个 `invoke()`；真正的业务仍由 `method.invoke(star, args)` 交给原对象。

### Star 独有的方法能被当前代理调用吗？

假设 `Star` 另有一个没有声明在 `StarService` 中的方法：

```java
public void rehearse() {
    System.out.println("排练");
}
```

当前代理按 `StarService` 接口生成，不能通过 `proxy.rehearse()` 调用这个独有方法，也不能把代理强转为 `Star`。若要让 `rehearse()` 经过当前 JDK 代理，应将它声明到所代理的某个接口中，并由 `Star` 实现；也可以另学基于子类的代理，但那是另一种方式。

因此，本例讨论的 JDK 动态代理范围是**通过代理调用的接口方法**。Java 对代理的 `toString()`、`equals()`、`hashCode()` 也有特殊转发规则，不影响这里对业务方法的理解。

## 17.代理优化练习：统一统计用户业务方法耗时

对应 `demo5proxy2`。最初 `UserServiceImp` 的 `login()`、`deleteUsers()`、`selectUsers()` 各自记录开始和结束时间并打印耗时；现在这些重复代码已注释，三个方法只负责业务模拟。`Test` 改为通过代理调用：

```java
UserService userService = ProxyUtil.createProxy(new UserServiceImp());
userService.login("admin", "123456");
userService.deleteUsers();
String[] names = userService.selectUsers();
System.out.println(Arrays.toString(names));
```

这里左边仍是 `UserService`：JDK 生成的代理实现这个接口，**不是** `UserServiceImp` 的实例。直接调用 `new UserServiceImp().login(...)` 不会经过代理，也就没有代理打印的耗时。

### 一处代理逻辑覆盖三个方法

当前 `ProxyUtil.createProxy(T obj)` 是泛型方法，取得真实对象直接实现的接口，创建代理；无论调用三个接口方法中的哪一个，都会进入同一个处理器：

```java
long start = System.currentTimeMillis();
Object answer = method.invoke(obj, args);
long end = System.currentTimeMillis();
System.out.println(method.getName() + "方法耗时："
        + (end - start) / 1000.0 + "秒");
return answer;
```

`method` 表示本次调用的方法，`obj` 是原来的 `UserServiceImp`，`args` 是本次传入的参数。`method.invoke(obj, args)` 真正执行原方法，返回值保存在 `answer` 中，再交回调用者。所以 `selectUsers()` 的 `String[]` 仍能正常返回；`void` 方法得到的反射结果为 null。

```text
Test 调用接口方法
    → 生成的代理进入 invoke
    → 记录开始时间
    → 反射调用 UserServiceImp 的对应方法
    → 记录结束时间、打印耗时
    → 返回原方法的结果
```

把耗时统计从各业务方法集中到代理里，新增接口方法时也可以复用这套处理。这是“统一给多个调用加处理”的实际用途；**原业务方法没有被动态改写**。

### 泛型方法与使用边界

`<T> T createProxy(T obj)` 让工具在调用处看起来能返回相同类型，但当前写法内部有强制转换 `(T)`，编译器不能保证一定安全。它只适用于有接口的对象，并且调用方应使用代理实现的**接口类型**接收：

```java
UserService service = ProxyUtil.createProxy(new UserServiceImp()); // 本例可用
// UserServiceImp impl = ProxyUtil.createProxy(new UserServiceImp());
// 代理不是 UserServiceImp，不能这样接收
```

`obj.getClass().getInterfaces()` 只取得该类直接声明实现的接口。若对象没有接口，当前 JDK 代理方式无法按预期创建代理。

当前统计也有一个边界：如果真实方法抛异常，`method.invoke(...)` 之后的结束时间和输出不会执行；要连失败调用也计时，可把结束记录放在 `finally` 中。`System.currentTimeMillis()` 适合这个入门演示，做精细耗时测量时可使用 `System.nanoTime()`。

## 18.本章总结：从发现信息到统一处理调用

这一章的学习路线是：**用测试验证行为 → 用反射在运行时认识和操作类 → 用注解给类或方法留下标记 → 让程序读取标记并决定执行什么 → 用动态代理统一处理接口方法的调用。**

```text
@MyTest 标记方法
    → 反射找到方法并读取注解
    → 按 count 调用方法

调用 UserService 代理的方法
    → InvocationHandler 记录开始时间
    → 反射调用 UserServiceImp 的真实方法
    → 记录耗时并交还原结果
```

| 本章练习 | 关键 API 或语法 | 最重要的区别 |
| --- | --- | --- |
| JUnit 测试 | `@Test`、`Assert.assertEquals` | 打印结果供人看；断言自动检查预期 |
| 认识类 | `.class`、`Class.forName()`、`getClass()` | Class 描述类型，不是业务对象本身 |
| 操作成员 | `Constructor.newInstance()`、`Field.get/set()`、`Method.invoke()` | 取得私有成员与获准访问它是两步 |
| 自定义注解 | `@interface`、`@Target`、`@Retention` | 注解是元数据；执行效果来自读取它的代码 |
| 注解解析 | `isAnnotationPresent()`、`getAnnotation()` | 运行时反射读取需要 `RUNTIME` 保留策略 |
| JDK 动态代理 | `Proxy.newProxyInstance()`、`InvocationHandler` | 代理实现接口并拦截调用，不改写原实现类 |

### 回看自己的三个例子

1. `SaveObjectFrame` 不预先知道 Dog、Student、Teacher 的字段，借助 Class 和 Field 统一读取对象；私有字段在访问前需要 `setAccessible(true)`。
2. `AnnotationDemo4` 遍历方法，只有标了 `@MyTest` 的方法才执行，次数由注解的 `count` 决定。注解负责提供信息，反射负责真正调用。
3. `demo5proxy2` 把三个业务方法重复的计时代码集中到一个处理器中。通过 `UserService` 接口使用代理，真实业务仍由 `UserServiceImp` 完成，`selectUsers()` 的返回值要原样传回。

### 最容易弄错的边界

- 测试通过只证明当前断言成立，还要检查断言是否符合需求，例如 `getMaxIndex()` 返回的是长度还是最大下标。
- `getDeclaredField()` 能找到 private 字段，但 `field.get()` 仍可能因访问权限失败；`setAccessible(true)` 也受模块封装等限制。
- 注解本身不会自动执行方法；没有设置 `RetentionPolicy.RUNTIME` 的自定义注解，不能按本章方式在运行时读取。
- JDK 代理能作为它实现的接口使用，不能强转成原实现类，也不能通过它调用原类独有的业务方法。
- `method.invoke(obj, args)` 的对象要是真实对象；代理还要返回这个调用的结果。当前耗时统计只覆盖正常结束的调用。

最值得记住的两句话：**反射让程序在运行时处理原本不知道的类型和成员；注解说明“处理谁、怎样处理”，动态代理则为接口调用提供统一的处理入口。**
