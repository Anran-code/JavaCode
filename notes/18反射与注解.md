# 反射与注解笔记

对应 `18-junit-reflect-annotation-proxy` 中的 `demo1junit`、`demo2reflect` 和 `demo3annotation`。本次整理单元测试、反射、自定义注解与注解解析；动态代理留到学习后再补充。

## 1.JUnit 单元测试：

单元测试用于单独检查一个方法的行为，不必每次都从整个项目的 `main()` 开始运行。本模块使用 **JUnit 4**，导入的是 `org.junit.Test`。

```java
@Test
public void testGetMaxIndex() {
    Assert.assertEquals(-1, StringUtil.getMaxIndex(""));
}
```

- 本例测试方法写成 `public void`，无参数，并标记 `@Test`。
- `Assert.assertEquals(期望值, 实际值)` 自动比较结果，不相等时测试失败；也可以在最前面添加失败提示。
- 仅打印结果不等于验证正确性；断言才能明确表达预期。
- 测试要考虑正常值、空字符串、`null` 等边界。

当前 `getMaxIndex("abcdefg")` 返回的是长度 7，测试也断言为 7。若按方法名理解为“最大有效下标”，应该是 6。**测试通过说明代码符合断言，不代表断言一定符合需求。**

## 2.什么是反射？

反射是在程序运行时，获取类的信息，并动态创建对象、访问字段和调用方法的机制。

```text
Class 对象
├── Constructor：构造方法 → 创建对象
├── Field：字段 → 读取、修改数据
└── Method：方法 → 调用行为
```

普通写法是事先知道类，再直接 `new Dog(...)`、调用方法；反射把“类有哪些成员、要操作哪个成员”也变成运行时可以处理的数据，适合通用工具和框架。

## 3.获取 Class 对象：

`ReflectDemo1` 演示了三种写法：

```java
Class<Student> c1 = Student.class;
Class<?> c2 = Class.forName("com.ranan.demo2reflect.Student");
Student student = new Student();
Class<?> c3 = student.getClass();
```

| 写法 | 使用场景 |
| --- | --- |
| `类名.class` | 编译时已经知道类型 |
| `Class.forName("全限定类名")` | 类名来自字符串，例如配置 |
| `对象.getClass()` | 已有对象，获取其实际运行类型 |
| `getName()` | 获取包名和类名，例如 `com.ranan.demo2reflect.Student` |
| `getSimpleName()` | 获取简单类名，例如 `Student` |

在本例相同类加载器下，三种方式取得同一个类的 `Class` 对象。它描述类本身，不是某一个学生实例。笔记使用 `Class<?>` 等泛型写法，减少源码中原始类型 `Class` 带来的不明确转换。

## 4.获取成员：普通获取与 Declared 获取

| API | 获取范围 |
| --- | --- |
| `getConstructors()` | 当前类的 public 构造方法 |
| `getDeclaredConstructors()` | 当前类声明的所有构造方法，包括 private |
| `getFields()` | public 字段，包括继承而来的 public 字段 |
| `getDeclaredFields()` | 当前类声明的字段，包括 private，不包含父类声明的字段 |
| `getMethods()` | public 方法，包括继承的方法 |
| `getDeclaredMethods()` | 当前类声明的方法，包括 private，不包含父类声明的方法 |

单数形式用于精确查找，例如 `getDeclaredField("hobby")`、`getDeclaredMethod("eat", String.class)`。**获取到 private 成员，不等于已经有权限使用它。**

构造方法不继承；反射返回的成员数组也不要依赖其排列顺序与源码一致。

## 5.Constructor：创建对象

```java
Class<Dog> c = Dog.class;
Constructor<Dog> con = c.getDeclaredConstructor(String.class, int.class);
Dog dog = con.newInstance("小狗", 2);

Constructor<Dog> empty = c.getDeclaredConstructor();
empty.setAccessible(true);
Dog another = empty.newInstance();
```

`Dog` 的无参构造方法是 private，因此调用前需放开访问检查。查找构造方法时传入的是**参数类型**，创建对象时传入的是**参数值**；`int.class` 与 `Integer.class` 不一样，查找时要匹配实际声明。

`getParameterCount()` 可以取得参数数量。

## 6.Field：读取与修改字段

```java
Dog dog = new Dog("小狗", 2);
Field field = Dog.class.getDeclaredField("hobby");
field.setAccessible(true);
field.set(dog, "play");
String hobby = (String) field.get(dog);
```

| API | 含义 |
| --- | --- |
| `getName()` | 字段名 |
| `getType()` | 字段声明的类型，返回 Class 对象 |
| `get(对象)` | 读取这个对象的字段值，返回 Object |
| `set(对象, 值)` | 修改这个对象的字段值 |

这里 `field` 描述“hobby 这个字段”，而 `dog` 指定“读取哪一只狗的数据”。静态字段属于类，反射访问时对象参数可以传 `null`。

反射写字段不会自动调用 setter，所以也不会自动执行 setter 中的校验。

## 7.Method：调用方法

```java
Dog dog = new Dog("小狗", 2);
Method eat = Dog.class.getDeclaredMethod("eat", String.class);
String answer = (String) eat.invoke(dog, "bone");

Method privateEat = Dog.class.getDeclaredMethod("eat");
privateEat.setAccessible(true);
privateEat.invoke(dog);
```

`invoke(调用对象, 实际参数...)` 执行方法并返回结果；无返回值方法返回 `null`，静态方法的调用对象可传 `null`。方法名相同但参数不同，需要分别查找对应重载。

若被调用的方法内部抛出异常，反射调用通常以 `InvocationTargetException` 包装它，可通过 `getCause()` 查看原始异常。

## 8.之前遇到的 IllegalAccessException：

`SaveObjectFrame` 已通过 `getDeclaredFields()` 找到 `Dog` 的私有字段，但直接执行 `field.get(obj)` 时仍会检查访问权限，所以此前出现了：

```text
IllegalAccessException: cannot access ... with modifiers "private"
```

当前代码已在读取前添加：

```java
field.setAccessible(true);
Object value = field.get(obj);
```

`setAccessible(true)` 表示请求关闭该反射对象的 Java 语言访问检查，并不是把字段本身改成 public。它也不是对所有类都有效：受到模块封装等限制时仍可能失败。日常业务优先使用公开方法，反射用于确有需要的通用处理。

## 9.反射与泛型擦除：

`ReflectDemo3` 对 `ArrayList<String>` 反射调用 `add(Object)`，加入了 `9.1` 和 `true`。

```java
List<String> list = new ArrayList<>();
Method add = list.getClass().getDeclaredMethod("add", Object.class);
add.invoke(list, 9.1);
```

泛型主要在编译阶段检查，擦除后 `ArrayList.add()` 接收 Object。反射绕过了这次编译期类型检查，但并没有让混入的对象变成 String；后续按 String 读取时可能出现 `ClassCastException`。

## 10.SaveObjectFrame：反射的通用处理练习

处理过程：接收 Object → `getClass()` 获取实际类 → 遍历字段 → 读取字段名、类型和值 → 追加写入文本文件。

因此同一个 `saveObject(Object obj)` 可以处理 Dog、Student、Teacher，而不用为每种类单独写一套输出代码。

当前实现的几个边界：

- 使用 `getDeclaredFields()`，只处理当前类声明的字段，没有向父类逐层查找。
- 文件路径是相对工作目录的 `18-junit-reflect-annotation-proxy/src/obj.txt`，不是固定相对 Java 文件所在位置。
- 当前 `PrintStream` 未关闭，宜使用 try-with-resources；`obj == null` 也尚未处理。
- 这是把字段转成文本的练习，不是完整的对象序列化框架，也没有实现从文件恢复对象。

## 11.什么是注解？

注解（Annotation）是附加在类、方法、字段等位置的**元数据标记**，与 `//`、`/* */` 这样的注释不同。注解本身不会自动执行业务，编译器、注解处理器或运行时程序读取它后，才会做对应处理。

例如 `@Override` 供编译器检查重写关系，JUnit 读取 `@Test` 来识别测试方法，Lombok 的 `@Data` 等由编译期处理器生成代码。不能把所有注解都理解成“运行时通过反射执行”。

## 12.自定义注解与属性：

```java
public @interface MyBook {
    String name();
    int age() default 18;
    String[] address();
}

@MyBook(name = "Anran", address = {"Beijing", "Shanghai"})
class BookDemo { }
```

声明注解使用 `@interface`。属性写成无参方法的形式；有 `default` 的属性可以省略，没有默认值的必须填写。常见属性类型包括基本类型、String、Class、枚举、注解，以及这些类型的一维数组。

当本次只需要填写名为 `value` 的属性时，可以省略 `value =`：

```java
@A("ANRAN") // 等价于 @A(value = "ANRAN")
```

其他属性只要有默认值，也不影响这个简写规则。注解类型隐式继承 `java.lang.annotation.Annotation`；反射取得注解对象后，通过 `注解对象.属性名()` 读取值，不要把源码中的标记理解为普通的手写 `new` 表达式。

## 13.元注解：规定注解怎么使用

```java
@Target({ElementType.METHOD, ElementType.TYPE})
@Retention(RetentionPolicy.RUNTIME)
public @interface MyTest2 {
    String value();
    double price() default 100;
    String[] adddress();
}
```

这里保留源码中的属性名 `adddress`，使用和解析时必须与声明一致。

| 元注解 | 作用 |
| --- | --- |
| `@Target` | 限制注解可标记的位置 |
| `@Retention` | 指定注解保留到哪个阶段 |

常用位置：`TYPE` 类/接口等类型声明、`FIELD` 字段、`METHOD` 方法、`PARAMETER` 参数、`CONSTRUCTOR` 构造方法、`LOCAL_VARIABLE` 局部变量。

| 保留策略 | 含义 |
| --- | --- |
| `SOURCE` | 只保留在源代码中 |
| `CLASS` | 保留到 class 文件，默认策略；通常不能通过运行时反射获取 |
| `RUNTIME` | 保留到运行时，可以通过反射读取 |

**运行时要解析自定义注解，就要使用 RUNTIME。** 当前 `A`、`MyBook` 没有声明 Retention，因此默认是 CLASS；`MyTest`、`MyTest1`、`MyTest2` 则设置了 RUNTIME。

## 14.解析类和方法上的注解：

`AnnotationDemo3` 分别解析 Demo 类和它的 `go()` 方法：

```java
Class<Demo> c = Demo.class;
if (c.isAnnotationPresent(MyTest2.class)) {
    MyTest2 annotation = c.getAnnotation(MyTest2.class);
    System.out.println(annotation.value());
    System.out.println(annotation.price());
    System.out.println(Arrays.toString(annotation.adddress()));
}

Method method = c.getDeclaredMethod("go");
MyTest2 annotation = method.getAnnotation(MyTest2.class);
```

| API | 作用 |
| --- | --- |
| `isAnnotationPresent(注解类型.class)` | 判断是否存在该注解 |
| `getAnnotation(注解类型.class)` | 获取指定注解，不存在时返回 null |
| `getDeclaredAnnotation(...)` | 获取直接声明在当前元素上的指定注解 |
| `注解对象.value()` 等 | 读取属性值 |

类上的注解和方法上的注解是两个独立位置，要获取对应的 Class 或 Method 再解析，不会因为类有注解就自动让每个方法都有同样的注解。

## 15.模拟 JUnit：注解和反射结合

`AnnotationDemo4` 使用自定义 `@MyTest(count = 3)`，表示标记的方法需要执行三次：

```java
for (Method method : AnnotationDemo4.class.getDeclaredMethods()) {
    if (method.isAnnotationPresent(MyTest.class)) {
        int count = method.getDeclaredAnnotation(MyTest.class).count();
        for (int i = 0; i < count; i++) {
            method.invoke(annotationDemo4);
        }
    }
}
```

最终 Test1 执行 1 次，Test3 执行 3 次；Test2、Test4 没有标记，不执行。反射枚举方法的顺序不保证固定，因此不要求 Test1 一定先执行。

当前简化版假设被标记的方法无参数且可访问，也没有为每个测试单独捕获异常；某个方法抛异常会中断后续执行。完整测试框架还需要处理方法合法性、断言、异常收集和测试报告。

## 16.本阶段总结：

| 技术 | 回答的问题 |
| --- | --- |
| Class | 这是哪个类？ |
| Constructor / Field / Method | 怎样创建对象、访问数据、执行方法？ |
| 注解 | 哪些地方做了标记，标记里配置了什么？ |
| 注解解析 | 怎样读出这些标记？ |
| 框架逻辑 | 读到标记后，决定执行什么操作？ |

**注解提供信息，反射提供动态操作能力，框架代码把二者连接起来。**
