# 实战02：图书管理系统

对应 `anran-library-sys`。使用 Swing 实现登录、注册、图书查询、借还书、充值、办卡和会员升级，并区分管理员与普通用户界面。当前数据保存在内存中。

## 1.项目结构：

```text
anran-library-sys/
├── src/design.txt                 需求设计
├── src/App.java                   启动入口
├── src/com/ranan/library/
│   ├── bean/                      账号、会员、图书
│   ├── data/LibraryData.java      共享数据与账号、会员管理
│   └── ui/
│       ├── LoginFrame.java
│       ├── UserLibrarySystemFrame.java
│       └── AdminLibrarySystemFrame.java
└── test/                          业务与数据测试
```

数据类保存状态并提供业务方法，LibraryData 管理共享集合，界面负责收集输入、调用方法、展示结果。

## 2.两套继承体系：

```text
LoginUser（登录身份）             Member（抽象类，借阅业务）
├── Admin：管理员                ├── NormalUser：普通用户规则
└── User：普通用户账号             └── VipUser：VIP 规则
```

`User` 和 `Member` 不是同一个对象：前者保存登录名和密码，后者保存会员编号、余额、持卡状态和借阅记录。`LibraryData.findMember(User)` 通过同名关联两者。

注册时必须同步创建 User 和 NormalUser，否则可能出现“登录成功，却没有会员资料”的问题。登录后按 `instanceof User / Admin` 打开不同界面。

## 3.会员规则与多态：

| 规则 | NormalUser | VipUser |
| --- | --- | --- |
| 未持卡时每次借书费用 | 1 元 | 0.8 元 |
| 最多同时借书数量 | 5 本 | 10 本 |
| 办卡费用 | 20 元 | 15 元 |
| 升级 | 扣除 50 元，创建 VIP 资料 | 已经是 VIP |

持卡时借书不再按次扣费，但仍受库存和借书上限限制。**借书卡状态由手动维护，系统不自动计算到期日或月费。** 设计中的“月卡”目前只用 boolean 表示是否有效。

```java
Member currentMember = LibraryData.findMember(account);
boolean success = currentMember.rentBook(book);
```

左边用父类 Member 统一接收，实际调用 NormalUser 或 VipUser 重写的方法。界面不用分别写两套借书流程，这就是继承、抽象方法与多态的结合。

## 4.集合与共享对象：

| 数据 | 用途 |
| --- | --- |
| `loginList` | 保存 LoginUser，包含普通账号和管理员 |
| `memberList` | 保存 Member，包含普通会员和 VIP |
| `bookList` | 保存馆藏 Book 对象 |
| 每位会员的 `rentList` | 保存这个会员借到的 Book 引用 |

Book 包含书名、ISBN、总量 count、可借量 available。借书只减少 available，还书只增加 available，总馆藏数量 count 不因借还变化。

借阅列表保存的是馆藏中的**同一个 Book 对象**。若复制一个 Book 再修改库存，改到的可能只是副本，馆藏表就不会同步。

`getRentList()` 返回新 ArrayList，防止外部直接增删会员内部列表；但元素仍是原 Book 引用，这是浅拷贝。`LibraryData.getBooks()` 等返回不可增删的列表视图，也不意味着其中 Book 的字段不可修改。

## 5.借书与还书的更新顺序：

借书：检查参数、上限、库存 → 未持卡时检查并扣费 → 添加借阅记录 → 根据列表 size 更新借书数量 → 可借库存减 1。

关键是**先检查能否成功，再修改状态**，不能借书失败了却已经扣费或减少库存。

还书：按 ISBN 查找自己的借阅记录 → 删除其中一条 → 更新借阅数量 → 把记录中原 Book 的库存加 1。没有找到记录就返回 false，不增加库存；有多条同 ISBN 记录时，一次归还一本。

借还操作成功后，界面再刷新馆藏表、个人信息和借阅表。表格是数据的显示结果，不是业务数据本身。

## 6.会员升级为什么要替换对象？

NormalUser 不能通过一次类型转换就变成 VipUser。`toBeVipUser()` 创建新的 VipUser，保留姓名、ID、持卡状态和借阅记录，并扣除升级费用。

```java
VipUser vip = member.toBeVipUser();
memberList.set(index, vip);
```

用户界面还需要同步更新引用：

```java
currentMember = LibraryData.upgradeToVip((NormalUser) currentMember);
```

只创建新对象而不替换集合和窗口中的旧引用，后续操作就仍可能按普通用户规则执行。复制借阅记录使用 `addAll()`，保留的仍是相同馆藏对象引用。

## 7.界面与事件：

| 界面 | 主要功能 |
| --- | --- |
| LoginFrame | 校验空输入、账号重复和密码，区分登录身份 |
| 用户界面：图书页 | 搜索书名或 ISBN，右键借书 |
| 用户界面：个人页 | 查看自己的资料与借阅记录、还书、充值、办卡、升级 VIP |
| 管理员：图书页 | 指定会员 ID 借书，查看该书被谁借走并操作还书 |
| 管理员：用户页 | 搜索用户、查看借阅情况、充值、办卡 |
| 管理员：全部借阅页 | 汇总借阅记录，选择一条还书 |

两个主界面都有退出登录入口：关闭当前窗口，回到 LoginFrame。同一次运行内共享集合仍保留。

`JTabbedPane` 组织不同页面；`JTable + DefaultTableModel` 展示数据；`JPopupMenu` 提供行右键操作。无库存时禁用借书菜单，业务方法中也再次检查库存。

## 8.搜索与表格行的对应：

用户界面维护 `visibleBooks` 和 `visibleRentBooks`，与表格模型中的行一一对应。刷新时同时清空显示列表和模型，再把匹配对象与显示行一起加入。

```java
String keyword = searchField.getText().trim().toLowerCase(Locale.ROOT);
if (book.getName().toLowerCase(Locale.ROOT).contains(keyword)
        || book.getISBN().toLowerCase(Locale.ROOT).contains(keyword)) {
    visibleBooks.add(book);
    bookTableModel.addRow(new Object[]{book.getName(), book.getISBN(),
            book.getCount(), book.getAvailable()});
}
```

上面是遍历馆藏时的筛选片段。空字符串是任意字符串的子串，所以搜索为空时会显示全部图书。选中视图行后使用 `convertRowIndexToModel()` 转成模型行，再取得对应显示列表中的对象，不能把筛选后的行号直接当原始馆藏集合下标。

## 9.全部借阅情况怎样汇总？

设计稿曾提出 `Map<String, String>` 保存“用户 ID → ISBN”，但同一个用户可以借多本书，单个值会覆盖之前的 ISBN。**当前实现没有用这个 Map 作为借阅数据源**。

`collectLoans()` 遍历每个 Member，再遍历其 `getRentList()`，把会员和图书组成 `LoanEntry`，生成展示用列表。可按某个会员或某本图书筛选，也可以传 null 表示不过滤。

```text
memberList → 每位会员的 rentList → LoanEntry(Member, Book) → 借阅表
```

因此不需要同时维护另一套独立借阅账本；展示信息从已有集合汇总，实际还书仍调用该会员的 `returnBook()`。

## 10.输入校验与初始数据：

充值时把字符串解析成 double，捕获 `NumberFormatException`；还要拒绝非正数、NaN、无穷大和导致余额溢出的金额。检查通过后调用 `topUp()`。当前 `topUp()` 本身只是加法，这些检查主要在界面入口。

LibraryData 用静态初始化准备账号、会员与图书，再调用真实的 `rentBook()` 生成示例借阅记录，而不是分别手写库存和借书数量，这样多处状态保持一致。

## 11.技术总结与当前边界：

| 技术 | 项目用途 |
| --- | --- |
| 抽象类、继承、重写、多态 | 不同会员使用不同计费与上限规则 |
| ArrayList 与对象引用 | 保存账号、馆藏和借阅记录 |
| 静态共享数据 | 不同窗口使用同一份数据 |
| 内部类 LoanEntry | 临时组合会员和图书，供表格展示 |
| Swing 事件与模型刷新 | 用户操作驱动业务，再更新界面 |
| 返回 boolean 与异常 | 表示业务成功失败，处理非法输入等情况 |

当前没有数据库，重启程序会恢复初始数据；没有自动到期、真实支付或完整的账号安全机制。金额用 double 是本次练习的简化，真实计费应考虑精确金额表示。

这个项目的重点是：**一份业务数据、多种界面视图；统一调用业务方法，保持余额、库存和借阅记录一致。**
