综合项目实战：局域网内的沟通软件
需求：展示一个用户的登录界面，这个界面要求用户输入自己聊天软件的昵称就可以了
登录进入后，展示一个群聊的窗口，展示在线人数，展示消息展示框，发送按钮，可以实现群聊，实现实时展示在线人数，完全做到即时通讯功能

技术选型：
1.GUI编程技术
2.网络编程
3.面向对象设计
4.常用API

思路分析：
1.创建一个模块，代表项目
2.拿到系统需要的界面：Swing的代码
    --登陆界面：这个界面要求用户输入自己聊天软件的昵称就可以了（GUI）
    --聊天界面：中间是聊天区，下侧是输入区，右侧展示在线的人（目前只实现窗口）
3.设定一个App启动类
4.分析系统的整体架构
    开发服务端：
        --接收客户端的管道连接
        --接收登陆消息，接受昵称消息
        --服务端也可能是接收客户端发送过来的群聊消息
        --服务端存储全部在线的socket管道，以便知道哪些客户端在线，需要向哪些客户端转发消息
        --如果服务端有了登陆消息，接受昵称，然后更新客户端在线人数列表
        --如果服务端收到了群聊消息，接受这个人的消息，然后发送给所有客户端展示这个消息
    客户端界面准备好了
5.开发服务端
    --创建服务端项目anran-network-server-sys
    --创建服务器启动类，启动服务器等待客户端连接
    --定义一个集合容器存储所有登陆进来的客户端管道，以便将来群发消息给他他们
        --一个记住所有socket
        public static final Map<Socket,String> onlineSocket = new HashMap<>();
6.服务端线程开始接收登陆消息/群聊消息
            // 接受的消息可能有多种类型：
            // 1.登陆消息 2.群聊消息 3.私聊消息
            // 所以客户端必须声明协议发送消息
            // 比如先发1代表登录 先发2代表群聊消息
    int type = dis.readInt();
                switch (type) {
                    case 1:
                        // 客户端发来了登陆消息，接下来要接收昵称数据，再更新全部在线客户端的在线人数列表
                        break;
                    case 2:
                        // 客户端收到了群聊消息，接下来要接收群聊消息内容，再把群聊消息转发给全部在线客户端
                        break;
                    case 3:
                        // 客户端发来了私聊消息，接下来要接收私聊消息内容，再把私聊消息转发给指定客户端
                        break;
                }
7.实现服务端的登陆消息接受
8.实现服务端的群聊消息接受
    线程每收到一个客户端的群聊消息，就应该把这个消息转发给全部在线socket管道
9.完善整个客户端程序的代码
    第一步：从登陆界面开始
        给这个进入按钮绑定一个点击事件监听器，让他可以点击，一旦点击了，获取到昵称，然后立即请求于服务器端的socket的链接
        并立即发送登录信息
        再展示客户端界面：接收到了昵称，接收到了属于自己客户端的socket管道通信
    第二步：立即在消息聊天界面，立即读取客户端socket管道从服务端发来的在线人数更新消息/群聊消息
        交给一个独立的线程专门负责读取客户端socket从服务端收到的在线人数更新数据和群聊数据
        收到消息，先判断消息的2类型，判断是在线人数更新消息还是群聊消息，分开处理
    第三步：接收群聊消息
        接收消息类型GROUP_CHAT_MESSAGE，展示到面板上即可
    第四步：发送群聊消息
        给发送按钮绑定事件，把输入框的内容捕获，再发送GROUP_CHAT_MESSAGE消息给服务端
    第五步：开发私聊功能：
        右键点击要私聊的对象，在鼠标位置显示小菜单（私聊二字），点击私聊，就弹出一个私聊窗口
        私聊窗口基本类同群聊，但title显示为“与xxx1私聊 - xxx2”
    第六步：发送私聊功能
        类同于第四步
    第七步：接收私聊消息
        指定的接收者socket收到消息类型PRIVATE_CHAT_MESSAGE，在私聊界面展示消息
        但值得注意的是：若接收者事先没有打开私聊界面，需要在发信人的名字后面显示数字提示，表示接收到了有多少消息
        当其打开时，应立即加载这些新消息（这里做简化处理：对于关闭了私聊界面后，再次打开不要求显示历史记录）
